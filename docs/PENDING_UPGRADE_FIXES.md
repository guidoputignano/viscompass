# Pending upgrades and fixes — Pillars A, B and C

**Register opened 12 October 2026.** One list of what is still to fix or build across the three pillars, for the general review that will take them in a single sweep. Nothing here is fixed yet unless its status says so. Detail and evidence live in the linked documents; this file is the index.

## How to use it

- **IDs are stable.** Cite them in commits. Close an item by setting its status to `done (<commit>)` and adding the verification that proves it; do not delete rows.
- **Status words:** `open` · `partly done` · `awaiting input` (owner, clinician or data provider) · `parked` (an owner decision holds it) · `needs live verification` (done in code, not yet proven on the live site or database) · `merged into <ID>` · `superseded` · `done (<commit>)`.
- **Priorities:** P1 confidentiality, security, or a defect a user can see or be misled by · P2 next · P3 polish. For Pillar B and the cross-cutting items, P3 polish is listed in the assessment, not here; Pillar A lists every priority. Where the adversarial verifier proposed a different priority, the row shows both (`P1 (verifier: P2)`): decide each before ordering the work.
- **Verdicts** (Pillar B and cross-cutting): `confirmed` = verified in the code or the live evidence; `partly` = real, but overstated or the fix needs adjusting (the verifier's correction is in the Fix cell); `found by verifier` = missed by the panel, found and checked by a verifier.
- **This repository is public.** No release figures, no per-Azienda values, no reviewer addresses in this file or in the fixes. Unfixed security weaknesses and the locations of confidential figures are recorded in the private evidence repository (`outputs/pillar-b`, not in git here); rows that depend on them say so. Production migrations, imports and access changes still need the owner's explicit approval; a register entry is not that approval.
